# Collabo IDE — 서브프로세스 관리

실제 작업은 **별도의 Python 서브프로세스**로 실행되며, 그 결과가 가운데 **대화창**에
메시지로 추가됩니다. Collabo IDE는 이러한 프로세스를 **동시에 여러 개** 띄우고 관리합니다.

## 동작 흐름

```
   대화창(웹)            네이티브(Flutter)              Python 서브프로세스
      │  작업 요청            │                                │
      ├─────────────────────►│  프로세스 spawn                 │
      │                      ├───────────────────────────────►│
      │                      │                                │ (작업 수행)
      │                      │◄── stdout/결과 스트리밍 ─────────┤
      │◄── 결과 메시지 추가 ──┤                                │
      │                      │◄── 종료(exit code) ─────────────┤
      │◄── 완료 표시 ─────────┤                                │
```

1. 사용자가 대화창에서 작업을 요청.
2. 네이티브(Flutter)가 Python 서브프로세스를 **spawn**.
3. 프로세스의 출력(stdout/stderr/결과)을 네이티브가 받아 **대화창에 메시지로 추가**.
4. 프로세스 종료 시 완료 상태를 반영.

## 핵심 요구사항

- **다중 동시 실행**: 여러 프로세스가 동시에 돌 수 있음. 각 프로세스는 고유 ID로 식별.
- **프로세스 매니저**: 네이티브 측에서 실행 중 프로세스 목록·상태·수명주기를 관리.
- **결과 → 대화창**: 각 프로세스의 출력/결과는 해당 대화 맥락에 메시지로 누적.
- **진행 상태 표시**: 좌측 설정 버튼 바로 위 **진행 상태 아이콘**에 실행 중 프로세스를 힌트로 표시.

## 프로세스 매니저 (네이티브)

| 책임             | 설명                                              |
|------------------|---------------------------------------------------|
| spawn            | Python 인터프리터/스크립트로 새 프로세스 시작        |
| 식별             | 프로세스별 고유 ID 부여, 대화 세션과 연결            |
| I/O 중계         | stdout/stderr 스트림을 읽어 웹뷰(대화창)로 전달      |
| 상태 추적        | running / finished / failed / canceled 등 상태 관리 |
| 종료/취소        | 사용자 요청 또는 앱 종료 시 프로세스 정리            |
| 동시성 관리      | 다수 프로세스 동시 실행, (필요 시) 동시 실행 수 제한  |

> 구현 위치: `lib/src/process/process_manager.dart`,
> `lib/src/process/launcher_process.dart` (프로세스 모델)

## Python 인터프리터

모든 런쳐 스크립트/도구는 **사용자가 선택한 Python 인터프리터**로 실행된다.
(자동 다운로드 없음 — 설정 → 도구 → **Python 설정**에서 인터프리터를 직접 선택,
없으면 python.org 다운로드 링크 제공.)

- 선택 경로는 메인 DB 설정(`python_interpreter`)에 저장된다.
- **패키지 직접 관리**: 이 인터프리터의 `python -m pip` 로 설치/목록 관리.

| 구성요소           | 역할                                            | 위치                                    |
|-------------------|-------------------------------------------------|-----------------------------------------|
| `PythonEnvironment` | 인터프리터 경로, 설치/버전 확인, pip 헬퍼          | `lib/src/process/python_environment.dart` |

## 관리자 권한 상승 (프로세스별 on-demand)

- 평소엔 일반 권한으로 실행하고, **필요한 스크립트만** 관리자 권한으로 상승 실행한다
  (`LaunchSpec.elevated == true`).
- **Windows**: `Start-Process -Verb RunAs` 로 UAC 동의 창을 띄워 상승.
  - 상승된 프로세스는 부모 파이프를 상속할 수 없으므로, 출력/종료코드를
    **임시 파일로 중계(file relay)** 하고 부모가 이를 tail 해 대화창으로 전달한다.
- **Linux/macOS**: pkexec/osascript 기반 상승은 추후 구현(현재 미지원).

## 진행 상태 아이콘 (Activity Indicator)

- 위치: 좌측 메뉴, **설정 버튼 바로 위**.
- 표시:
  - 실행 중 프로세스가 1개 이상이면 활성/애니메이션 상태.
  - **힌트(툴팁)** 로 실행 중 프로세스 목록과 상태 표시.
  - 동시 실행 개수 배지 등.
- 클릭 동작(확장 패널/취소 등)은 추후 확정.

## 브리지 메시지 (예정)

| 방향          | 메시지(예시)         | 용도                          |
|---------------|---------------------|-------------------------------|
| Web → Flutter | `process.start`     | 작업 실행 요청 (명령/인자 포함) |
| Web → Flutter | `process.cancel`    | 특정 프로세스 취소             |
| Flutter → Web | `process.output`    | stdout/stderr 청크 전달        |
| Flutter → Web | `process.status`    | 상태 변경(시작/종료/실패) 통지  |
| Flutter → Web | `process.list`      | 실행 중 프로세스 목록(상태 아이콘용) |

> 메시지 페이로드 스키마는 브리지 설계 단계에서 확정.

## 설정 연동

설정 창에 **Python 환경 / 패키지 관리** 기능이 포함된다. (별도 탭 또는 섹션)

- Python 인터프리터 선택·상태 확인(버전)·경로 표시.
- pip 패키지 목록 보기 / 설치 / 제거.
- (향후) 동시 실행 상한선 등 런쳐 옵션.

## 미결정 사항

- 프로세스당 작업 단위와 대화 세션의 매핑 규칙.
- 동시 실행 상한선 설정 여부 (설정 창에서 조정 가능하게 할지).
- Linux/macOS 권한 상승 메커니즘 확정(pkexec vs sudo vs osascript).
