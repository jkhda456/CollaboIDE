# Collabo IDE — 화면 레이아웃

메인 화면은 **네이티브 좌측 메뉴 + 웹뷰 영역**의 2개 최상위 영역으로 구성됩니다.
좌측 메뉴만 Flutter 네이티브 위젯이며, 그 외 모든 영역(가운데 대화 + 우측 트리/뷰어)은
**하나의 웹뷰** 안에서 렌더링됩니다.

```
┌──────┬───────────────────────────┬──────────────────────────┐
│ ▣    │                           │  📁 project/             │
│ ▣    │                           │   ├── lib/               │
│ ▣    │      대화 내용             │   │   └── main.dart      │
│ ▣    │      (Conversation)       │   ├── docs/              │
│      │                           │   └── README.md          │
│ [<]  │                           │  ────────────────────────│
│ 좌측  │                           │  선택된 파일 뷰어          │
│ 메뉴  │                           │  (File Viewer)           │
└──────┴───────────────────────────┴──────────────────────────┘
  Left          Center                     Right
│네이티브│◄──────────────  단일 WebView  ───────────────────────►│
│Flutter │  (가운데 대화 + 우측 트리/뷰어 분할은 웹 내부에서 구현)    │
```

> **아키텍처 핵심**: 가운데/우측의 분할(대화 영역, 트리, 파일 뷰어, 그 사이 splitter)은
> 모두 웹(HTML/CSS/JS) 안에서 구현됩니다. Flutter는 좌측 메뉴와 창 셸만 담당합니다.

> **웹뷰 UI 기본 디자인**: 웹뷰 영역의 기본 스타일은 **Bootstrap** 기반으로 합니다.
> (그리드/컴포넌트/모달 등 Bootstrap 컴포넌트 활용)

## 1. 좌측 — 네비게이션 메뉴 (Left Nav)

- 아이콘 + 설명(라벨)으로 구성된 세로 메뉴.
- **접기/펼치기(collapsible)** 가능: 접으면 아이콘만, 펼치면 아이콘 + 설명 텍스트.
- 토글 버튼으로 폭을 전환 (예: `[<]` / `[>]`).

| 상태   | 표시            | 예상 폭     |
|--------|-----------------|------------|
| 접힘   | 아이콘만        | ~56px      |
| 펼침   | 아이콘 + 라벨   | ~220px     |

### 메뉴 구성

```
┌──────┐
│ 📂   │  ← 최상단: 프로젝트 열기 (Open Project)
│ 열기  │
├──────┤
│ 🅐   │  ← 최근 프로젝트 (MRU): 아이콘으로 최대 5개
│ 🅑   │
│ 🅒   │
│ ...  │  ← (그 외 메뉴는 추후 추가)
├──────┤
│ ◌    │  ← 진행 상태 (Activity) : 실행 중 프로세스 힌트
├──────┤
│ ⚙    │  ← 최하단: 설정 (Settings)
│ 설정  │
└──────┘
```

- **최상단 — 프로젝트 열기**:
  - 클릭 시 네이티브 폴더 선택 다이얼로그를 띄움.
  - 선택한 경로가 **작업 경로(working directory)** 가 됨.
  - 작업 경로가 정해지면 그 하위 내용이 **우측 트리뷰**에 표시됨.
  - 폴더 선택은 네이티브(Flutter) 기능이므로, 선택 결과 경로를 웹뷰로 전달 → 웹이 트리 렌더링.
- **최근 프로젝트 (Recent Projects, MRU)**:
  - "프로젝트 열기" 버튼 **바로 아래**에 아이콘으로 쌓임.
  - **최대 5개**까지 보관. 한 번 열었던 폴더가 목록에 추가됨.
  - 가장 최근에 연 항목이 위로 오는 MRU(Most Recently Used) 순서.
  - 클릭 시 해당 경로를 바로 작업 경로로 다시 엶.
  - 목록은 **네이티브 앱 설정**에 영구 저장 ([설정 저장](#설정-저장-위치) 참고).
- **진행 상태 아이콘 (Activity)** — 설정 버튼 **바로 위**:
  - 현재 **실행 중인 서브프로세스**가 있으면 활성 상태로 표시.
  - 마우스 오버 시 **힌트(툴팁)** 로 실행 중 프로세스 목록/상태를 보여줌.
  - 실행 중 프로세스 수 배지 등으로 동시 실행 현황을 암시.
  - 상세는 [프로세스 관리](process-management.md) 참고.
- **최하단 — 설정(⚙)**:
  - 클릭 시 **설정 창**을 띄움 ([4. 설정 창](#4-설정-창-settings) 참고).

## 2. 가운데 — 대화 내용 (Center / Conversation)

- 핵심 작업 영역. 대화(채팅) 형태의 내용이 표시됨.
- 화면 가변폭의 대부분을 차지 (flex).

## 3. 우측 — 프로젝트 트리 + 파일 뷰어 (Right)

세로로 두 영역으로 분할됩니다. (웹 내부 구현)

- **상단: 트리뷰** — **좌측 "프로젝트 열기"로 선택한 작업 경로** 하위의 파일/폴더 트리.
  - 작업 경로가 없으면 빈 상태(안내 메시지) 표시.
  - 작업 경로가 정해지면 해당 경로 기준으로 트리를 렌더링.
  - **트리 헤더(상단)**: **경로**(고정 텍스트, 편집/이동 불가) + 🔍 **파일 검색 아이콘**.
    아이콘 클릭 시 검색 입력창이 펼쳐지며 **경로 표시를 덮어쓴다**(취소/Esc 로 복귀).
- **하단: 파일 뷰어** — 트리에서 선택한 파일의 내용 표시.
  - **뷰어 헤더**: **파일명**(고정 텍스트) + 🔍 **내용 검색 아이콘**.
    아이콘 클릭 시 검색 입력창이 **파일명 표시를 덮어쓴다**(취소/Esc 로 복귀).
- 두 영역 사이는 드래그로 높이 조절(splitter) 가능.
- **우측 패널 전체 폭**은 가운데와의 경계 splitter 를 드래그해 조절(웹 내부).

```
┌─ 우측 패널 (평소) ────────────┐   ┌─ 검색 활성 ───────────────────┐
│ 경로 .................   🔍  │   │ [ 파일 이름 검색…   ] [취소]  │
│ ── 파일 트리 ──────────────   │   │ ── 파일 트리 ──────────────   │
│   ├ lib/                      │   │   ├ lib/                      │
│   └ README.md                 │   │   └ README.md                 │
│ ─────────────────────────── │   │ ─────────────────────────── │
│ 파일명.dart            🔍    │   │ [ 파일 내용 검색…   ] [취소]  │
│ ── 파일 내용 ──────────────   │   │ ── 파일 내용 ──────────────   │
└───────────────────────────────┘   └───────────────────────────────┘
```

## 4. 설정 창 (Settings)

좌측 메뉴 최하단 ⚙ 아이콘을 누르면 나타나는 설정 화면.

- **탭(tab) 형태**로 여러 설정 그룹을 전환.
- 예정 탭/항목:
  - **모델 설정(Model)** — 사용할 모델, API Key 등.
  - **모양(Appearance)** — 테마(라이트/다크). **기본 라이트**. *(설정 저장은 구현됨,
    UI 토글은 설정 창 구현 시 연결)*
  - **Python 환경** — 포터블 Python 설치 상태/패키지 관리
    (참고: [process-management.md](process-management.md)).

```
┌─────────────────────────────────────┐
│  설정                            [×] │
├──────────┬──────────────────────────┤
│ ▸ 모델    │   모델 설정                │
│ (추후 탭) │   ┌────────────────────┐  │
│          │   │ 모델: [ ▼ ]         │  │
│          │   │ API Key: [______]   │  │
│          │   │ ...                 │  │
│          │   └────────────────────┘  │
└──────────┴──────────────────────────┘
```

- **모델 설정 탭** 항목(예정): 사용할 모델 선택, API Key 등.
  - 구체 항목은 추후 확정.
- 설정 창이 웹뷰 내부 모달인지 별도 네이티브 창인지는 추후 결정 (현재는 웹뷰 내 모달을 기본 가정).

## 영역별 분할 동작

- **좌측 메뉴 ↔ 웹뷰** 경계: 네이티브 Flutter splitter로 폭 조절.
- **가운데 ↔ 우측**, **우측 트리 ↔ 파일 뷰어** 경계: 웹 내부 splitter로 조절.
- 좌측 메뉴는 접힘/펼침 토글로 폭 전환.

## 구현 위치 (예정)

### 네이티브 (Flutter)

| 영역             | 위치                                |
|------------------|------------------------------------|
| 앱 전역 상태      | `lib/src/app/workspace_controller.dart` |
| 전체 레이아웃     | `lib/src/ui/app_layout.dart`        |
| 좌측 메뉴         | `lib/src/ui/left_nav.dart`          |
| 웹뷰 패널         | `lib/src/webview/web_view_panel.dart` (Windows=`webview_windows`) |

- **프로젝트 열기**: `app_layout` 이 `file_selector` 로 폴더를 고르면
  `WorkspaceController.openProject()` 가 대화 DB 를 열고 메인 DB 의 MRU 를 갱신한다.
  최근 프로젝트는 좌측 메뉴에 반영된다.
- **웹뷰**: Windows 는 `webview_windows`(WebView2)로 웹 UI 를 로드한다.
  모든 웹 리소스(HTML/CSS/JS, Bootstrap 포함)는 앱에 **임베딩**되며, 실행 시
  `<appSupport>/web/` 로 추출 후 `file://` 로 로드한다 → **CDN 없이 오프라인 동작**.
  그 외 플랫폼은 아직 플레이스홀더(추후 백엔드 연결).

### 웹 (WebView 내부 — 가운데 대화 + 우측 트리/뷰어)

가운데 대화 영역, 우측 트리뷰, 파일 뷰어, 그리고 이들 사이의 splitter는
모두 웹 자산(HTML/CSS/JS) 안에서 구현한다. 초기 골격은 `assets/web/index.html`
(Bootstrap 5, **로컬 임베딩** `assets/web/vendor/`) 의 정적 목업이며, 현재 프로젝트
경로만 `window.collaboSetProject()` 로 전달하는 임시 연동 상태다.
정식 Flutter ↔ Web 브리지는 추후 단계.

## 데이터 소스 & 책임 분담

| 데이터 / 기능        | 담당               | 비고                                        |
|---------------------|-------------------|---------------------------------------------|
| 폴더 선택 다이얼로그  | 네이티브 (Flutter) | OS 다이얼로그                                |
| 트리뷰 데이터        | 네이티브 (Flutter) | 파일시스템을 **직접 읽어** 웹뷰로 전달 → 웹이 렌더링 |
| 파일 내용(뷰어)      | 네이티브 (Flutter) | 선택 파일을 읽어 웹뷰로 전달                  |
| 트리/뷰어 UI 렌더링   | 웹 (WebView)      | Bootstrap 기반                               |
| 모델 설정 / 기본 설정 | 네이티브 앱        | 아래 [설정 저장](#설정-저장-위치) 참고          |
| 최근 프로젝트 목록    | 네이티브 앱        | 최대 5개 MRU, 영구 저장                       |

> 웹뷰는 OS 파일시스템에 직접 접근하지 않습니다. 모든 파일시스템 접근은 네이티브가 수행하고
> 결과(트리 구조, 파일 내용)만 브리지를 통해 웹뷰로 전달합니다.

### 설정 저장 위치

- **모델 설정, 기본 설정, 최근 프로젝트 목록**은 모두 **네이티브 앱 쪽**에 영구 저장.
- 저장 매체(설정 파일 경로/형식)는 구현 단계에서 확정. (예: 앱 데이터 디렉토리의 설정 파일)

## Flutter ↔ WebView 브리지

좌측 네이티브 메뉴와 웹뷰 콘텐츠가 협력하려면 양방향 메시지 채널이 필요합니다. (상세 설계 예정)

- **Flutter → Web**: 메뉴 클릭, 프로젝트 열기/경로 변경, **트리 데이터·파일 내용 전달** 등.
- **Web → Flutter**: 파일/디렉토리 읽기 요청, 설정 읽기·쓰기, 프로세스 실행 등 OS 기능 호출.
